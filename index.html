Signal is a network diagnostics application for analyzing Wi-Fi, mobile network and internet connection quality, checking user-selected network destinations and examining devices on a local network. Signal does not require a user account and does not contain advertising or behavioral analytics.

2. Information Processed on the Device

Signal processes technical network information made available by Android, depending on device capabilities, permissions and the selected diagnostic function.

This information may include:

  • Wi-Fi signal strength and RSSI values.
  • SSID and BSSID of wireless networks.
  • Wi-Fi frequency, channel, channel width and standard.
  • Information about nearby Wi-Fi networks.
  • Mobile network type and connection status.
  • Mobile signal values such as RSRP, RSRQ, RSSI and SINR.
  • Technical SIM and subscription information required to identify active mobile connections.
  • Local IP addresses and network configuration.
  • Latency, jitter, packet loss and other diagnostic measurements.

These values are used to display network conditions and perform the diagnostic functions requested by the user. Signal does not use this information to create advertising profiles or location histories.

3. Location Permission and Wi-Fi Scanning

Android may require location permission and enabled location services to provide information about the connected Wi-Fi network and nearby wireless networks.

Signal uses the relevant permissions for Wi-Fi analysis, including channel analysis and signal monitoring.

Signal does not request or record GPS coordinates for these functions and does not use Wi-Fi scanning to track the user's physical movements.

Wi-Fi identifiers and information about nearby networks may nevertheless be location-related information because they can potentially reveal a device's location.

4. Phone and Mobile Network Information

Signal may request Android phone-state permission to obtain technical information about active mobile subscriptions, SIM slots and mobile network conditions.

Signal does not use this permission to read phone calls, SMS messages or contacts.

5. Network Check

Signal performs network connectivity diagnostics to measure latency, jitter, packet loss and connection availability.

These tests may communicate with Cloudflare infrastructure, including:

  • 1.1.1.1
  • www.cloudflare.com/cdn-cgi/trace

When such connections are established, Cloudflare may receive the public IP address and other standard technical connection metadata. These requests are made for diagnostics, not for advertising or behavioral tracking.

Cloudflare's own data processing is described in its Privacy Policy.

6. Target Check

Target Check allows users to enter a domain name, URL or IP address to test its availability and technical connection quality.

Depending on the destination and supported protocols, Signal may perform:

  • DNS resolution.
  • ICMP latency and packet-loss measurements.
  • TCP connection tests.
  • TLS connection tests.
  • HTTP or HTTPS requests and response-time measurements.

The selected destination, its network operator and any DNS resolver involved may receive technical connection information. Depending on the request, this may include the public IP address, requested hostname, URL path and other standard protocol metadata.

These connections are initiated for the diagnostic function selected by the user. PureCore does not operate a central server collecting Target Check histories.

7. Local Network Scanner

Signal can examine devices and services within the user's local network. The scanner may process:

  • Local IP addresses.
  • Hostnames and device information made available by network services.
  • Reachability and response information.
  • Information about accessible ports and services.

Signal may send network requests directly to devices within the local network. The results are used for local network analysis and troubleshooting. Signal does not upload a collected local device inventory to a PureCore-operated server.

8. Wi-Fi Channel Analysis and Repeater Placement

Wi-Fi Channel Analysis examines nearby wireless networks, frequencies, channels and signal conditions using information provided by Android.

Repeater Placement displays live Wi-Fi signal information and statistical measurements to help users evaluate potential repeater locations.

These measurements and calculations are performed locally on the device. Signal does not create a physical movement or location history from them.

9. Local Storage and Android Backup

Diagnostic measurements may be temporarily held in device memory while a measurement is running.

Application preferences, such as language and display settings, may be stored locally using Android application storage.

Signal does not maintain a PureCore-operated cloud database of users' network measurements.

The application is configured to disable standard Android application backup. Device-to-device transfer behavior may additionally depend on the Android version, device manufacturer and system configuration.

Locally stored application data generally remains until changed, cleared or removed with the application, subject to Android's data-management behavior.

10. Purposes and Legal Bases

Technical information is processed to provide the network diagnostics selected by the user, including Wi-Fi analysis, mobile network analysis, connectivity tests and local network checks.

Where personal data processing is necessary to provide the purchased application's agreed functionality, Article 6(1)(b) GDPR may apply.

Where processing is not necessary for contractual performance, the provision, security and troubleshooting of technical functions may rely on legitimate interests under Article 6(1)(f) GDPR, subject to the required balancing of interests.

Connections to external diagnostic destinations occur as described in Sections 5 and 6. The recipients may process technical connection data under their own responsibilities and applicable legal bases.

Android permissions control access to certain device functions. Granting an Android permission does not automatically constitute consent under the GDPR.

11. External Recipients and International Transfers

Network diagnostics may involve Cloudflare, DNS resolvers and destinations selected by the user. These recipients may receive public IP addresses and technical connection metadata.

Cloudflare is an external provider for the diagnostic destinations described in Section 5. Its processing practices and information about international transfers are described in the Cloudflare Privacy Policy.

For user-selected destinations, the receiving operator and its location cannot be determined in advance. Depending on the destination and network routing, data may be processed outside the European Economic Area.

PureCore does not operate a developer-controlled analytics service receiving local Wi-Fi inventories or mobile signal histories.

12. Data Retention

Live measurement samples are generally processed temporarily during the relevant diagnostic operation.

Locally stored application preferences remain available until changed, cleared or removed with the application's data.

PureCore does not maintain a server-side retention period for diagnostic histories because no such central history is operated by PureCore.

External destinations may independently retain connection information according to their own policies and legal obligations.

13. Advertising, Analytics and Data Sales

Signal does not require registration or a user account. It does not contain advertising or use third-party behavioral analytics to create user profiles.

PureCore does not sell personal data obtained through Signal.

14. This Website (GitHub Pages)

This information page is hosted through GitHub Pages, a service provided by GitHub. When the page is accessed, the hosting infrastructure may process technical request data, such as the visitor's IP address, request time, requested page, browser information and security-related metadata, to deliver and protect the website.

Providing a functioning and secure information page serves the legitimate interest under Article 6(1)(f) GDPR, insofar as processing is attributable to the website operator. GitHub's own processing, retention and any international transfers are described in the GitHub Privacy Statement. PureCore does not embed advertising trackers or a separate analytics service in this page.

2. Auf dem Gerät verarbeitete Informationen

Signal verarbeitet technische Netzwerkdaten, die Android abhängig von den Gerätefunktionen, Berechtigungen und ausgewählten Diagnosefunktionen bereitstellt.

Dazu können gehören:

  • WLAN-Signalstärke und RSSI-Werte.
  • SSID und BSSID von WLAN-Netzwerken.
  • WLAN-Frequenz, Kanal, Kanalbreite und WLAN-Standard.
  • Informationen über benachbarte WLAN-Netzwerke.
  • Mobilfunkstandard und Verbindungsstatus.
  • Mobilfunksignalwerte wie RSRP, RSRQ, RSSI und SINR.
  • Technische SIM- und Abonnementinformationen zur Ermittlung aktiver Mobilfunkverbindungen.
  • Lokale IP-Adressen und Netzwerkkonfiguration.
  • Latenz, Jitter, Paketverlust und weitere Diagnosemesswerte.

Diese Daten werden zur Darstellung des Netzwerkzustands und zur Durchführung der vom Nutzer angeforderten Diagnosefunktionen verwendet. Signal erstellt daraus keine Werbeprofile oder Standortverläufe.

3. Standortberechtigung und WLAN-Scans

Android kann für den Zugriff auf bestimmte WLAN-Informationen eine Standortberechtigung und aktivierte Standortdienste voraussetzen.

Dies betrifft insbesondere Informationen über das verbundene WLAN und benachbarte Netzwerke.

Signal verwendet diese Berechtigungen für die WLAN-Analyse, beispielsweise zur Kanalanalyse und Signalüberwachung.

Signal fragt für diese Funktionen keine GPS-Koordinaten ab, zeichnet keine GPS-Koordinaten auf und verwendet WLAN-Scans nicht zur Verfolgung physischer Bewegungen.

WLAN-Kennungen und Informationen über benachbarte Netzwerke können dennoch standortbezogene Informationen darstellen, weil sie Rückschlüsse auf einen Standort ermöglichen können.

4. Telefon- und Mobilfunkinformationen

Signal kann die Android-Telefonstatusberechtigung benötigen, um technische Informationen über aktive Mobilfunkabonnements, SIM-Steckplätze und Mobilfunkverbindungen auszulesen.

Signal verwendet diese Berechtigung nicht zum Lesen von Telefonaten, SMS-Nachrichten oder Kontakten.

5. Network Check

Signal führt Netzwerkdiagnosen durch, um Latenz, Jitter, Paketverlust und Erreichbarkeit zu messen.

Hierfür können Verbindungen zur Cloudflare-Infrastruktur hergestellt werden, insbesondere zu:

  • 1.1.1.1
  • www.cloudflare.com/cdn-cgi/trace

Bei solchen Verbindungen kann Cloudflare die öffentliche IP-Adresse sowie übliche technische Verbindungsinformationen erhalten. Diese Anfragen dienen der Netzwerkdiagnose und nicht der Werbung oder verhaltensbasierten Nachverfolgung.

Informationen zur eigenständigen Datenverarbeitung durch Cloudflare enthält die Cloudflare-Datenschutzerklärung.

6. Target Check

Mit Target Check können Nutzer eine Domain, URL oder IP-Adresse eingeben, um deren Erreichbarkeit und technische Verbindungsqualität zu überprüfen.

Abhängig vom Ziel und den unterstützten Protokollen kann Signal folgende Prüfungen durchführen:

  • DNS-Auflösung.
  • ICMP-Latenz- und Paketverlustmessungen.
  • TCP-Verbindungsprüfungen.
  • TLS-Verbindungsprüfungen.
  • HTTP- oder HTTPS-Anfragen und Antwortzeitmessungen.

Der ausgewählte Zielserver, dessen Netzbetreiber und gegebenenfalls beteiligte DNS-Resolver können technische Verbindungsinformationen erhalten. Dazu können abhängig von der Anfrage die öffentliche IP-Adresse, der angefragte Hostname, URL-Pfade und weitere übliche Protokollinformationen gehören.

Diese Verbindungen dienen der vom Nutzer gestarteten Diagnose. PureCore betreibt keinen zentralen Server zur Sammlung von Target-Check-Messhistorien.

7. Local Network Scanner

Signal kann Geräte und Dienste innerhalb des lokalen Netzwerks untersuchen. Dabei können folgende Informationen verarbeitet werden:

  • Lokale IP-Adressen.
  • Hostnamen und von Netzwerkdiensten bereitgestellte Geräteinformationen.
  • Erreichbarkeit und technische Antwortinformationen.
  • Informationen über erreichbare Ports und Dienste.

Zur Durchführung dieser Prüfungen kann Signal Netzwerkanfragen direkt an Geräte innerhalb des lokalen Netzwerks senden.

Die Ergebnisse werden zur lokalen Netzwerkanalyse und Fehlersuche verwendet. Signal überträgt keine erfasste lokale Geräteliste an einen von PureCore betriebenen Server.

8. WLAN-Kanalanalyse und Repeater Placement

Die WLAN-Kanalanalyse untersucht benachbarte Funknetzwerke, Frequenzen, Kanäle und Signalbedingungen anhand der von Android bereitgestellten Daten.

Repeater Placement zeigt aktuelle WLAN-Signalwerte und statistische Messungen an, um Nutzer bei der Bewertung möglicher Repeater-Positionen zu unterstützen.

Diese Messungen und Berechnungen erfolgen lokal auf dem Gerät. Signal erstellt daraus keinen Bewegungs- oder Standortverlauf.

9. Lokale Speicherung und Android-Backup

Während einer laufenden Diagnose können Messwerte vorübergehend im Arbeitsspeicher des Geräts gehalten werden.

App-Einstellungen wie Sprache und Anzeigeoptionen können über die lokalen Speichermechanismen von Android gespeichert werden.

Signal betreibt keine eigene PureCore-Cloud-Datenbank für Netzwerkmesswerte der Nutzer.

Die Anwendung ist so konfiguriert, dass die reguläre Android-App-Datensicherung deaktiviert ist. Das Verhalten bei einer Übertragung von Gerät zu Gerät kann zusätzlich von der Android-Version, dem Gerätehersteller und den Systemeinstellungen abhängen.

Lokal gespeicherte App-Daten bleiben grundsätzlich erhalten, bis sie geändert, gelöscht oder bei der Deinstallation entfernt werden, vorbehaltlich der Datenverwaltung durch Android.
